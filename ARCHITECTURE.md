# vault-storage — Architecture

AI-agent-first knowledge base over a markdown tree. The markdown files (the private `vault-data` repo) are the source of truth; SQLite + `sqlite-vec` next to them is a fully rebuildable derived index providing lexical (FTS5) + semantic (BGE) search and typed-edge traversal behind a single-process `node:http` REST server. TypeScript throughout `src/`, run directly under Node type-stripping — no build step.

## Data flow

```
markdown tree (source of truth)
  → walk / importFile   → records (+ tags, chunks)
  → buildEdges          → edges (+ review suggestions)
  → embedPending        → record_vec / record_doc_vec / record_summary_vec
```

Reads go through REST handlers over the repositories plus `sqlite-vec` KNN, an in-memory chunk matrix for record-to-record similarity, and FTS5. Writes-in (`PUT /vault/{path}`, `PUT /sections/{id}`) land on disk first, then re-import inline. Background loops keep everything converged: the watcher (disk → DB), git-sync (tree → commits), the scan scheduler (periodic maintenance → suggestions), and incremental reindex (post-`git pull`). The MCP adapter and the static UI are pure REST clients.

## Entry points

- **`src/index.ts`** — CLI dispatcher: `info` (schema/record counts), `import` (importVault + embedPending), `migrate` (one-time Obsidian tree transform), `serve` (delegates to the server's `main()`). `makeEmbedder()` picks `BgeEmbedder` or `FakeEmbedder` via `VAULT_EMBEDDER`.
- **`src/server/index.ts`** — composition root: env, DB open + migrations, embedder (a `ChildProcessEmbedder` unless `VAULT_EMBEDDER=fake`), server (listening before the reindex, answering from the stored index), watcher (also before the reindex: a write landing during it is imported by its handler, and only a watcher drain embeds it), optional startup reindex (`startupReindex`), then memory reporter + git-sync, the startup embed (`embedAllPending`, not awaited: a backlog such as D45's re-chunk of every summarized note outlasts any startup wait, and runs in rounds a watcher drain can cut between), and the scan scheduler; git-sync starts after the reindex because it commits dirty files and advances the anchor past them. SIGINT/SIGTERM graceful shutdown: the listener closes first and the requests in flight answer (`ServerHandle.close`, five seconds at most), then the watcher drains and git-sync commits, so a write answered during a restart is on disk, indexed, and committed.
- **`src/server/server.ts`** — `buildRouter()` registers every route against shared repositories; request pipeline: URL parse → `OPTIONS` (pre-auth method discovery) → bearer-auth gate (`/ui/*`, `/favicon.ico` public) → route match → handler.
- **`src/server/router.ts`** — regex router; `{id}` → `([^/]+)`, `{path}` → `(.+)`. Registration order is precedence — literal routes before wildcards.
- **`src/server/body-fields.ts`** — the top-level JSON body fields each write route reads. After each handler the server records the route's JSON request and any field outside that list in `body_field_observations` (the body the handler read is kept by `body.ts`), and `GET /system/body-fields` reports them. The routes in `STRICT_BODY_ROUTES`, the ones with traffic and no unknown field over the first eight days, also refuse such a field with a 400 that lists the supported ones, checked in the request loop before the handler (`readBodyBuffer` hands the handler the body already read; D68); the rest are observed only (D64). `tests/test-body-fields.ts` fails when a write route is registered without a declaration.

## Import pipeline (`src/importer/`)

- **`import.ts`** — `importVault` / `importVaultAsync`: `walkMarkdown` → per-file `importFile`, one transaction per `IMPORT_BATCH_FILES` batch, then `buildEdges`. The async driver yields to the event loop between batches, and its edge pass is `buildEdgesAsync`, which yields too; the server uses it. A file that throws is skipped and recorded in `import_failures` (D113), as the watcher and the incremental reindex do per file; the edge pass records it too and keeps the edges of a record whose file does not parse, so one such file never stops a pass.
- **`import-file.ts`** — per-file stage: frontmatter parse, type/status/priority/date derivation, `agent:` block extraction, content hashes; skips unchanged files (hash + FM compare — dates at date granularity, see decision D3); files/auto-resolves `tag_suggestion` / `agent_enrichment_stale` / `archive_candidate`; records the enrichment baseline (below) whenever the `agent:` block is current; records in `fm_findings` every closed-enum value it defaulted (D103); sets `project` from the `project:` key, else from the path (`projects/<name>/…`, or a log whose name after the date starts with a project folder's name, the longest match; D104).
- **`walk.ts`** — recursive `.md` walker (skips `.git`, `node_modules`, `.obsidian`).
- **`type-from-path.ts`** — folder-default record-type inference (`_index.md` → index, `projects/*/state.md` → state, …).
- **`import-tags.ts`** — normalize + alias-rewrite FM tags; a set equal to the stored one writes nothing, a changed one is replaced whole; unknown tags file `new_tag` suggestions.
- **`build-edges.ts`** — second pass: FM `related:`/`edges:` + body wikilinks → resolved typed edges, stale-edge pruning, `edge_type` suggestions (one per default-cites link, filed already rejected as `default-cites` since D76, keeping the link's context for a later typing pass; a row reopened for review settles `fm-override` when the FM map pins the type, and is rejected `link-removed` once the body no longer carries the link — a moot question, not a verdict, so the pair re-files if the link returns). `buildEdges` runs scoped (the records a write touched) or whole in one transaction; a scoped pass reads every record's id and path for the resolver, and a body only for its own records and the counterparties of their stale edges, so a write's cost does not follow the vault's text; `buildEdgesAsync`, the whole pass for the server, commits and yields every `EDGE_BATCH_RECORDS` records, re-resolves after a write changes the path set, and spares edges touching a record written while it ran.
- **`classify-wikilinks.ts`** — heuristic edge classifier for body links (keyword cues; default `cites`).
- **`resolver.ts`** — wikilink target → record id (exact path, `.md`-stripped, unique basename, `_about.md` fallback).
- **`file-suggestions.ts`** — generic `SuggestionFiler` with per-kind idempotency, snooze semantics, and evidence provenance (`payload.evidence: {source, asserted}`, stamped per kind unless the caller supplies one).

## Embeddings (`src/embeddings/`)

- **`types.ts`** — the `Embedder` interface: `embed` and `embedBatch` for passages, `embedQuery` for search queries, where BGE adds its retrieval instruction (`BGE_QUERY_INSTRUCTION` in `model.ts`, D47).
- **`bge.ts`** — `Xenova/bge-small-en-v1.5` (384-dim, CLS-pool, L2-norm) via `@huggingface/transformers` ONNX on CPU; held by a `time-queues` Retainer that frees the ~GB arena after idle; `maxBatch` sub-batching; NaN-vector retry + logging.
- **`fake.ts`** — deterministic sha256-seeded unit vectors; used by tests and `VAULT_EMBEDDER=fake`.
- **`child-embedder.ts`** / **`embed-child.ts`** — `ChildProcessEmbedder`: the server's embedder, running `BgeEmbedder` in a forked child over advanced-serialization IPC, so inference never blocks the event loop (D44). Not a worker thread: onnxruntime-node's binding loads once per process, so a second thread or a restarted worker fails with "Module did not self-register". Mirrors `retained` from the child, restarts it on the next call after an exit, and exposes `pid` for the memory line. The CLI keeps `BgeEmbedder` in-process.
- **`model.ts`** — the model name and dimension, shared so the server never loads transformers.js on its main thread.
- **`chunker.ts`** — markdown-aware chunking: header-path prefixes, paragraph/char overlap, no chunk past the 1,500-character cap the embedder reads (an overlap that would push one past it is dropped, D46). The `agent.summary` is in no chunk; it has its own vector (D45).
- **`embed-pass.ts`** — `embedPending`: embeds the records whose chunks or summary vector carry a stale content hash, most recently modified first; reuses the stored vector of every chunk whose text hash (schema 0023) is unchanged and embeds the `agent.summary` on its own (D45), so an edit sends only its changed chunks to the model and a summary refresh sends one text; batch-embeds outside the transaction, writes per batch, and skips a record deleted or edited while its batch was at the model, whose vectors would otherwise outlive it or carry its old text (D114). `maxEmbeds` makes a call one round (`EMBED_ROUND` for the server's callers); `embedAllPending` loops rounds, each queued anew, so another pass runs between them. A record with a non-finite vector keeps its finite ones under an empty content hash, so lint reports it as drift, and is retried after a per-process backoff that doubles from a minute to an hour (D48). In-process, as in the CLI, each model call blocks the loop: onnxruntime-node wraps a synchronous `session.run` in `setImmediate`.
- **`embed-tags.ts`** — `embedTagsPending`: one vector per taxonomy tag from its name and description (schema 0030), refreshed by text hash at startup, by `POST /maintenance/embed-pending`, and on the way into `POST /tags/nearest`; a tag deleted or re-described while its batch was at the model is skipped the same way.
- **`anomaly-log.ts`** — append-only JSONL log of non-finite-vector events.

Vector storage: **`src/db/vec-repo.ts`** (per-chunk vectors; `nearest` ranks records by `recordSimilarity`, the better of the best chunk and the summary vector, exact through widening candidate lists; `nearestToRecord` by best chunk alone, one exact pass over **`src/db/chunk-matrix.ts`**, every chunk vector in one `Float32Array`, cached per database and rebuilt after a vector write, D78), **`src/db/summary-vec-repo.ts`** (one `agent.summary` vector per record, schema 0024), and **`src/db/doc-vec-repo.ts`** (one mean-pooled chunk vector per record; drives duplicate detection). An embed pass that wrote chunks warms the matrix in the background (`warmChunkMatrix`, D87), so the next reader finds it built; `/system/status` reports `chunk_matrix: {warm, rows, building}`.

## DB layer (`src/db/`)

- **`connection.ts`** — `node:sqlite` `DatabaseSync` + `sqlite-vec` extension, `sha256_hex` SQL function, FK enforcement, WAL. The server is the only process that opens the live database (D72); the CLI's `import`, `migrate`, and `info` are for a development database.
- **`migrate.ts`** — applies `schema/NNNN_*.sql` in numeric order, each in its own transaction (`-- migrate:no-transaction` opt-out for table rebuilds). A migration carrying a `-- migrate:no-reindex` line changes nothing the importer derives, so it does not force the startup full import; `MigrationResult.reindex` lists the ones that do.
- **`schema/`** — append-only numbered migrations (`0001_init.sql` …). Notable: 0004 doc-vecs, 0005/0006 agent enrichment, 0008 queue_items, 0013 FTS5 lexical index, 0023 `chunks.text_hash` (filled for existing chunk sets of unsummarized records by `backfillChunkTextHashes` at startup), 0024 `record_summary_vec`, 0027 `enrichment_baselines` (the body's chunk hashes and lengths when its `agent:` block was last current, written by `importFile` and, for records enriched before the table, by `backfillEnrichmentBaselines` at startup; `enrichment-baseline-repo.ts` diffs it against the current chunks), 0032 `fm_findings` (a stored frontmatter value outside its closed enum, one row per record, field, and value, written by `importFile` for `type`/`status`/`priority`/`agent.complexity` and by the edge pass for `edges:`, read by the lint; `fm-findings.ts`), 0033 `records.project` (D104; the resume bundle and brief read a project's own logs by it), 0034 `queue_items.source` (D107; the `source:` marker, which `insert-item` upserts by), 0035 `queue_items.section` admitting `inbox` (a table rebuild that keeps every row, `no-reindex`), 0036 `fleet_baselines` and `fleet_runs` (D110; the `## GitHub` and `## Packages` blocks of each `state.md` and the digest note's runs as JSON text, cascading with their record), 0037 `external_links` and `project_github` (D112; one row per mention of an outside object, and each queue's declared `github` tracker, cascading with their record), 0038 `import_failures` (D113; one row per file path whose import threw, with the error's first line, cleared by `importFile` when the path imports; read by the lint; `records/import-failures.ts`), 0022 partial expression indexes on the suggestion identity keys (their expressions must match `column()` in `file-suggestions.ts`, or the planner scans). A migration that rebuilds `records` must drop + recreate + `'rebuild'` the FTS5 external-content index.
- **`tag-vec-repo.ts`** — tag vectors: hashes in `tag_vec_meta`, vectors in the `tag_vec` vec0 table, KNN for the nearest-tag lookup; a taxonomy delete drops the row by trigger.
- **`meta.ts`** — typed KV: `schema_version`, `last_indexed_commit`, `content_generation`, git-sync failure ledger.

## Server surface (`src/server/handlers/`)

- **`records.ts`** — `GET /sections` (list/filter/paginate), record reads, FM PATCH, tag membership endpoints.
- **`records-write.ts`** — `PUT /sections/{id}`: write to disk at the record's path, re-import inline.
- **`vault.ts`** — path-addressed content API: `GET/PUT/DELETE /vault/{path}`, folder listing, `POST /vault/edit` (atomic append / asserted-replace / replace-section / remove-item / insert-item body edits, and replace-frontmatter; `GET …?section=` reads one section, `&occurrence=` picks among repeated headings, and its `hash` guards a later `replace-section`; `GET …?frontmatter=yaml` reads the block for `replace-frontmatter`), `GET …?render=html` and `POST /vault/render` (HTML through `src/render/`), `POST /vault/move-item` (one queue item between documents or sections, destination written first), `POST /vault/move|supersede|propose`.
- **`drafts.ts`** — `GET /drafts`, `PUT /drafts`, `DELETE /drafts/{id}`: the editor's unsaved edits, one per note and unit (document, frontmatter, or section), kept by `src/server/drafts.ts` as JSON files under `.vault-storage/drafts/` beside the database, never indexed or committed (D60).
- **`search.ts`** — `POST /search/simple`: FTS5 bm25 + title boost (lexical, the default) or `recordSimilarity` over chunk and summary vectors (semantic).
- **`similar.ts`**, **`edges.ts`** — nearest-neighbour records; typed-edge neighborhood (depth ≤ 5, the root record in the answer, `fields=` and `edge_fields=` projections with the ids always) + backlinks + `GET /edges`, the paged listing by type with per-type counts behind the edges page (D88).
- **`enrichment-delta.ts`** — `GET /sections/{id}/enrichment-delta`: the chunks added since the record's enrichment baseline, with the removed count and bytes and the changed fraction, so a stale refresh reads the change instead of the whole body. The threshold past which a refresh re-reads the body is the caller's.
- **`suggestions.ts`** — the agent review queue: list/summary/accept/reject/reopen.
- **`tags.ts`** — taxonomy listing + single-tag info (`GET /tags/{tag}`: description, aliases, count) + per-tag records + taxonomy/alias adds + the description rewrite (`PATCH /tags/taxonomy/{tag}`, the one field a mint leaves permanent otherwise).
- **`maintenance.ts`** — `POST /maintenance/*`: scans (duplicates, compaction, retention, upgrade signals), cleanups, log expiry, empty-tag collection (`gc-tags`, D77), embed-pending, a background model warm-up (`warm-embedder`, D80), incremental reindex, snapshots, raw inbox.
- **`queue.ts`** — queue-item slices (top, by-section, by-priority, per-project) plus the dependency views (`/queue/ready`, `/queue/blocked`) over query-time `blocked-by:` resolution.
- **`leases.ts`** — the repo-lease registry (agent coordination, D21/D23): list/events reads, atomic claim/renew/release/transfer with the human > cwd-agent > side-agent precedence lattice, plus a cwd claim taking a cwd lease unrenewed for `STALE_CWD_LEASE_SECONDS` (an hour). Leases are ephemeral — cleared on every server start and not restored, since a lock has no on-disk artifact to rebuild from.
- **`handoffs.ts`** — the handoff queue (agent coordination, legs 2–3): role-addressed work requests with an idempotent create, claim (lazy expiry), the D23 review-loop resolve (`done`/`rejected` archive into `projects/<project>/handoff-archive.md` and clear the spool entry; `returned` reopens for rework), resubmit, append-only notes, and the artifact pair (`PUT|GET /handoffs/{id}/artifact` — a 10 MB git patch or bundle, which sets the `spool` ref and travels with the sidecar). Unlike leases, handoffs survive restarts: the spool is truth, the table an index (see `src/records/handoff-spool.ts`). Handoffs declare `touches` (kind, key, operation), carry hash-bound `verifications` judged stale against the artifact on record (its sha256 when the gate was recorded), and the list reports `overlaps` between in-flight handoffs to one role.
- **`fleet.ts`** — `GET /fleet/status`: the stored fleet-status baselines and runs from the derivative `src/fleet/state.ts` keeps at import (`fleet_baselines`, `fleet_runs`; D110), narrowed by `?project=`, `?since=`, `?runs=`; a project read adds `tracked`, its open queue items that mirror a GitHub thread with the thread's stored state (D111).
- **`links.ts`** — `GET /links?key=|url=|repo=`: the notes and queue items that mention an outside object, from the index `src/links/external.ts` keeps at import (D112).
- **`system.ts`**, **`lint.ts`** — status; integrity checks + queue hygiene (`queue_hygiene`, over `src/queue/lint.ts`) + enrichment-coverage block (see decisions D4/D5). `resume-bundle.ts` adds the one-shot `/vault resume` bundle (POST, embedded reindex; the project block carries `notices`, the inbound `supersedes` and `contradicts` edges on the project's files, D90) and `trackers`, the project's tracker declaration read by `trackers.ts` from its `queue.md` frontmatter on disk (D95; `GET /projects/{name}/trackers` answers the same view for the project page and the `vault_project_trackers` tool) and its read-only brief tier (`GET /system/resume-brief`) for SessionStart-hook injection. `GET /system/health` answers from `health.ts`, the in-memory monitor git-sync and the watcher report into (watchdog lag, last outcomes, `stalled`), which never touches storage; `util/git.ts` kills a git child after `GIT_TIMEOUT_MS`.
- **`tag-nearest.ts`**, **`tag-check.ts`** (in `src/server/`) — the nearest-tag lookup behind `POST /tags/nearest` and the write path's unknown-tag answer: a `tags:` entry the taxonomy does not know writes and answers 200 with `unknown_tags` and candidates, or is refused with 409 under `strict_tags` (D82, D83). **`edge-check.ts`** — the write path's typed-edge answer: the `edges:` map's types checked against the closed vocabulary (400 `invalid_enum_value`), its targets resolved (200 with `unresolved_edges`, or 409 under `strict_edges`); `build-edges.ts` stores an entry the body never links as declared, so the map is the document's relation declaration, not only an override (D92).
- **`commit.ts`**, **`resolve.ts`**, **`static.ts`** — explicit git commit; wikilink resolution, one link per GET or a note's batch per POST; UI file serving.

**`sessions.ts`** parses and formats a project's session records (`projects/<name>/sessions.md`, one bullet per session end, written by claude-config's SessionEnd hook; D105), which the resume bundle and brief read. Background/lifecycle modules in `src/server/`: **`git-sync.ts`** (auto-commit loop with backoff and stale-lock recovery), **`watcher.ts`** (debounced `fs.watch` → incremental import/delete/embed), **`writer.ts`** (the disk-write + FM-validation core: auto-managed keys, closed-enum validation, the `"__unset__"` key-removal sentinel over the union-only FM merge, the opt-in replace mode, ETag), **`snapshot.ts`** (`VACUUM INTO` gzip snapshots for Tier-2 backup). Support: `env.ts`, `auth.ts` (constant-time bearer check), `body.ts`, `query.ts`, `responses.ts`, `serialize.ts`, `resolver-cache.ts`, `memory-reporter.ts` (its line appends `embedder_rss`, the embedding child's resident memory).

## Other modules

- **`src/records/`** — closed-enum types (`types.ts`), `RecordsRepository` / `EdgesRepository`, lazy decay scoring; reservation machinery (`claims.ts` for suggestion batches, `leases.ts` for the repo-lease registry; every agent claim, a handoff's included, issues a `claim_token` that the claim's later writes must present, so a holder name is a label and never a fence, D67); the handoff queue (`handoffs.ts` composing the DB index with `handoff-spool.ts`, the file layer under root `handoff/<project>/<status>/<id>.md` — self-describing sidecars plus an optional `<id>.patch`/`.bundle` artifact beside them, status transitions as atomic renames over every `<id>.*` sibling, rebuild-by-scan on server start).
- **`src/fleet/`** — `state.ts`: the fleet-status derivative (D110). `parseSection` and `parseRuns` read the JSON blocks the `fleet-status` skill writes (the same readers as `static/ui/fleet-digest.js` and the CLI), and `FleetStateRepository.apply` keeps a record's rows in step with its path from `importFile` and from `POST /vault/move`; a deleted record's rows cascade. `threads.ts` (D111): `githubThread` reads a queue item's `source:` as a GitHub issue, PR, discussion, or advisory, `GithubThreadStates` looks its state up in the stored baseline of the repository the source names (parsed once per repository per request), and `trackedItems` lists a project's open items with that state for the route; the brief's `in_flight` reads the same.
- **`src/links/`** — `external.ts`: the index of external links (D112). `extractMentions` reads a body with code masked: every http(s) URL, keyed per vendor by `linkKey` in `source:` spelling (`github o/r#n`, `figma <file>`, `sentry`, `slack`, `gitlab`, `bitbucket`, `linear`, `jira`, else `url <normalized>`), a queue's `source:` lines, a qualified `o/r#n`, and a bare `#n` kept unresolved with the note's project. `ExternalLinksRepository.apply` runs from `importFile` and from `POST /vault/move` (which recomputes `records.project` with it); `byKey` and `byRepo` resolve a bare `#n` through `project_github`, else the stored baseline's repository, and name the queue items that hold each mention. Statements are prepared once per database.
- **`src/queue/`** — parse `queue.md` / `queue-archive.md` into `queue_items` rows (the sections `Inbox` (untriaged intake from a secondary tracker, 2026-09-30), `Active`, `Backlog`, `Watching`, and the archive; including `blocked-by:` refs and the `source:` marker, the outside ticket an item mirrors, which every queue slice serves as `source` and `openBySource` finds for the insert-item upsert); query-time blocker resolution + ready/blocked/cycle computation (`ready.ts`); the queue-hygiene rules (`lint.ts`) that `/system/lint` and `/queue/lint` run over every `queue.md`; the slice sync every import runs (`importFile`'s `queueItems` option, which `importer/import-options.ts` always supplies), the drop for a deleted or renamed file, and the full reindex. `queue/items.ts` locates one item by its bold title and removes or inserts it — the server side of the queue-to-archive move.
- **`src/maintenance/`** — the find-\* scans, lint cleanups, incremental reindex (one run per database at a time; an optional working-tree pass), startup reindex (a full import when there is no anchor, a migration ran, or the importer fingerprint changed), run-all bundle, scan scheduler, search-before-write propose, raw-inbox classification, doc-vec backfill.
- **`src/markdown/`** — YAML frontmatter parse/serialize; wikilink extraction with code-region masking; `sections.ts` scans the ATX heading lines (fence-masked) and locates one section (exactly once, to the next same-or-higher heading) for the section read, `replace-section`, and the rendered note's section list.
- **`src/render/`** — markdown to HTML with `marked`: `render.ts` resolves wikilinks, marks short references (`#233`, `owner/repo#233`, `ENG-123`; `refs.ts`), and stamps each top-level heading with its document line, `render-worker.ts` runs it on a worker thread, and `renderer.ts` owns that worker, the time limit, and the cache keyed by body and by the resolver's path-set version. The marks are resolved per request, outside the cache (`src/server/refs.ts`): the project's declared trackers give the repository and the keys, and the GitHub baseline in its `state.md` gives the titles, so a render makes no network call.
- **`src/migration/`** — one-time Obsidian → vault-storage transform: enum remaps, tag canonicalization, frontmatter backfill, oversized-file atomization, taxonomy seeding.
- **`src/util/`** — git spawn wrapper, content/embed-input hashing, UUIDv7 ids.

## mcp/ subpackage

Standalone stdio MCP ↔ REST adapter (plain JS, no local state), published to npm as `@uhop/vault-storage-mcp` (`mcp-*` tags mark releases; run via `npx`):

- **`src/index.js`** — entry: env (`VAULT_API_URL`, `VAULT_API_TOKEN`), `McpServer` over stdio, tool + resource registration, and an unawaited `POST /maintenance/warm-embedder` at startup (D80).
- **`src/client.js`** — fetch wrapper adding base URL + bearer, error normalization, `If-Match` / `ETag` pass-through, and the network policy (D99): a refused connection is repeated every half second for eight seconds whatever the method, a read after any network failure, and a write whose connection dropped is reported with its cause and never repeated.
- **`src/tools.js`** — one tool per REST endpoint, with zod schemas mirroring the server's closed enums, at parity with the REST surface: reads, writes, lifecycle (`supersede`/`move`/`propose`), `/maintenance/*`, and the coordination families (`vault_lease_*`, `vault_handoff_*`), so the `/vault ingest`, `sweep`, `learn` and `resume` workflows all run MCP-native. Writes split by blast radius: `vault_append` / `vault_replace` / `vault_replace_section` / `vault_patch_fm` change only what they name (atomic server-side ops), while `vault_write_file` / `vault_update_piece` replace a whole document and take an optional `expected_etag`.
- **`src/resources.js`** — read-only resources: `vault://status`, `vault://suggestions/pending`, `vault://taxonomy/tags`.

## static/ UI

## Tests

~65 `tests/test-*.ts` files on tape-six. Standard pattern: in-memory SQLite, `FakeEmbedder`, config passed as literal objects (no `VAULT_*` env reads); server tests bind a real HTTP server on loopback. `tests/test-bge-embedder.ts` is the one non-hermetic test — it loads the real model (~33 MB download on a cold cache; CI caches that directory between runs, keyed on the lockfile). Three tests shell out to the real `git` binary.

## bin/, scripts/, skills/, eval/

- **`bin/update.sh`** — update a deployed instance; **`bin/vault-curl`** — authenticated curl wrapper for the REST API.
- **`scripts/probe-unresolved.ts`**, **`scripts/scan-promotable-edges.ts`** — one-off DB probes; **`scripts/ui-style-snapshot.mjs`** — computed-style snapshot of every UI page at 1280 and 400 px over a fixture vault, and the diff of two snapshots (the rendered-comparison gate for CSS changes); **`scripts/mcp-smoke.mjs`** — consumer smoke for the adapter: spawns the staged `mcp/src/index.js` and speaks JSON-RPC over stdio to the live server (the handshake, `tools/list` against what `registerTools` declares, `vault_health`, one read tool, one `fields=` subset), run before `npm publish` in `mcp/`; **`scripts/ui-preview.mjs`** — screenshot preview of the UI pages over a copy of the live vault's state documents (`fixture` copies them into a scratch directory by read-only GETs; `shoot` serves them in-process and takes one shot per `name|path|width|scheme[|hover]` spec, printing the horizontal overflow, page errors, console errors, and every response of 400 or above, plus a selector's top offset with `--measure=`).
- **`skills/`** — Claude Code vault skills (see `skills/README.md`).
- **`eval/`** — retrieval-quality harnesses over an imported DB: baseline report, the `agent.summary` query A/B (prefix, bare chunks, summary vector; D45), related-candidate proposals, alternate-model trials. `related-to-classify.mjs` is the related-to classification harness over the API, not the database (D72): `sample` builds the labelled and related-to sets from the typed edges and the judged `edge_type` rejections, `ask` runs Jev's choice and nouls arms, `rules` fits a record-type majority table, `reference` writes the batches a judging agent answers, and `score` reports precision and recall per type against the always-none floor (D93); its data files stay outside the repository.
